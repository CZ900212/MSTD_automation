## 5. 执行模型(每个任务的标准流程)

### 5.1 分工与 subagent 纪律(2026-07-13 裁决,覆盖旧版)
- **写代码**:主线程亲写,或派 subagent 承接。**所有 subagent 一律用 Terra 模型;
  禁用 Luna;旧版"代码环节可用 Fable subagent"的例外已作废。**
  同一时刻至多一个实现线程;辅助搜索/机械杂务另派 Terra(简单的用 haiku)。
- **禁用 claude-api skill**:主会话不得调用;委派 subagent 时必须在 prompt 里明确禁用。
- **对抗性代码审核(强制)**:实现完成、单测全绿后,派一个与实现者不共享上下文的
  独立审核 subagent,唯一目标是证伪:逻辑漏洞、边界破坏、§3 铁律逐条对照、并发竞态、
  假修复;拿不准按"有错"报,每条给触发场景。主线程逐条仲裁,确认的当场修+复审一轮,
  驳回的在日志写明理由。零缺陷才算过。
- **对抗性测试审卷(强制)**:TDD 先行(失败测试→实现→全绿),全绿后再派一个
  与实现者、代码审核者都不共享上下文的独立 Terra 审卷 subagent,输入 = 需求原文 +
  测试 diff + 实现 diff,唯一目标是证明这些测试保护不了需求:找假绿(断言太弱/永真)、
  漏掉的边界用例、测试与需求不符、对实现细节过拟合、可被 skip 绕过的结构。
  清单逐条处置(补测试/改断言/驳回并记录理由),处置完再跑全量。有条件时加一轮
  变异测试自查:随机挑 2-3 处实现做语义变异,变异后套件必须变红,杀不死就补杀。
- **写代码、审代码、审测试必须是三个互不共享上下文的线程**——你可以亲写代码,
  但不能独自给自己的测试定案,这是防自我确认偏误的结构性要求。

### 5.2 任务完成的定义
实现 + 单测全绿 + 对抗代码审核零缺陷 + 对抗测试审卷处置完毕
(+ 批次末 E2E 与真机剧本)。五者缺一,不许在 commit 或日志里写"完成"。

### 5.3 验证体系(缺一层不算"验证过")
```bash
# 单测(基线只增不减;禁止 skip/only/删测试造绿)
cd mstd-orchestrator && npx vitest run
cd mstd-ui && npx vitest run

# E2E:五套只能串行,一次一套,先杀本地常驻进程(E2E 自拉被测进程)
pkill -f server/index.mjs
bash scripts/e2e-one.sh <suite>   # persona / write / p2p / group / full
```
- E2E 门控环境变量缺一个会整套 skip 伪装成绿:`MSTD_E2E=1`、`MSTD_TEST_OPEN_IDS`、
  `MSTD_TEST_CHAT_IDS`;**full 套还需 `MSTD_ENABLE_WRITE` 门控,否则假绿**。
  脚本的 JSON 门禁(success && passed>0 && 无 skipped/pending/todo)是硬标准。
- E2E 打真飞书 API,不进小改动循环;每完成一个任务批次、或改动触及出入站链路时跑。
- 真机剧本(可扩充不可缩减):①群里 @小达 问公司事实;②5 条闲聊后点名复述
  (不漏不错不静默);③私聊建任务走四道锁;④要一张对比表(卡片渲染);
  ⑤翻文档/日历/任务类提问("上周聊了什么/今天有什么会");⑥跨会话提醒弹确认卡;
  ⑦诱导跨会话复述→稳定拒绝(迭代三新增)。

## 6. 无限迭代主循环

```
loop:
  1. 评估:读工作日志最后一轮评分卡 + model_log 异常 + §4 路线图未完条目
  2. 选题:路线图未完 → 按序取下一任务;已完 → 取评分卡最弱维度立一条新需求
  3. 实施:TDD(失败测试 → 实现 → 全量单测绿)→ 对抗性代码审核(§5.1)
  4. 审卷:独立 subagent 对抗性测试审卷,清单处置完毕
  5. 验证:分层验证(§5.3;批次末 E2E + 真机剧本)
  6. 评分:更新评分卡。任何维度比上一轮低 → 本轮判回归,当场修复或 revert,不带病提交
  7. 提交:中文 commit `type(mstd): 摘要`,更新文档与工作日志
  8. 通信:卡用户决策 → 问题信;阶段性成果或事故 → 报告信(§8)
  9. goto loop(永不退出;没题可选就读真实会话日志找失败案例,总能找到)
```

节流与自保:
- 同一错误连修 3 次不动 → 停止蛮试,写清"现象/已试/假设"发邮件,转做别的。
- 不可逆动作(删数据、改飞书后台、给真人发消息、合 main、生产开闸、bash 收权方案落地)
  → 除非本文件或用户邮件明确授权,先邮件确认。
- commit 粒度小而完整;工作树不留隔夜未提交改动;>1 小时不提交不写日志 = 事故。
- 上下文被压缩后,以工作日志 + git log 恢复状态,不凭记忆猜。
